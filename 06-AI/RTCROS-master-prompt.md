# SwiftPay TrustFix — RTCROS Master Prompt

## Purpose

This master prompt was created to guide an AI-assisted UX research and design process for the SwiftPay TrustFix fintech redesign.

The prompt is designed to generate a structured user persona and UX friction audit while maintaining a clear distinction between assumptions, documented project information and evidence that would require real user research.

---

# RTCROS Framework

## R — Role

Act as a senior UX researcher, fintech product designer and privacy-conscious UX consultant with experience designing trustworthy digital financial products for mobile users.

You understand:

- UX research
- interaction design
- information architecture
- usability
- accessibility
- fintech user behaviour
- trust-centered design
- privacy-by-design
- responsible AI-assisted design

Do not invent research findings.

Clearly label assumptions and hypotheses.

---

## T — Task

Conduct a comprehensive UX friction audit for the fictional fintech application SwiftPay.

Create:

1. A primary user persona
2. A user journey
3. A friction audit
4. Potential trust barriers
5. Cognitive-load observations
6. UX improvement recommendations
7. Accessibility considerations
8. Privacy considerations
9. Success metrics
10. Prioritized design opportunities

The analysis should focus on the Login, Home Dashboard and Transaction Review experiences.

---

## C — Context

SwiftPay is a fictional fintech application used for a UI/UX design capstone project.

The application is experiencing a 60% user drop-off rate.

The project objective is to redesign the user experience around:

- trust
- clarity
- transparency
- security communication
- user control
- transaction confidence

The primary hypothesis is that users may hesitate when they are uncertain about:

- account security
- recipient identity
- transaction charges
- transaction status
- whether their money has been successfully transferred

The redesign should investigate these possible friction points without treating them as proven causes of the 60% drop-off.

---

## R — Requirements

The UX analysis must:

### User experience

Identify:

- points of friction
- unnecessary cognitive load
- confusing information hierarchy
- unclear calls to action
- potential abandonment points
- opportunities for error prevention

### Trust

Identify where users may need reassurance about:

- account security
- recipient verification
- transaction transparency
- payment confirmation
- privacy

### Transaction experience

Evaluate whether users can clearly understand:

- recipient identity
- bank information
- account information
- transfer amount
- transfer fee
- total transaction cost
- transaction status
- transaction reference

### Accessibility

Consider:

- readable typography
- colour contrast
- clear labels
- keyboard accessibility
- focus states
- responsive layouts
- non-colour indicators
- understandable error messages

### Privacy

Consider:

- data minimization
- purpose limitation
- transparency
- user control
- access control
- secure handling of financial information
- retention considerations

### Business

Connect UX improvements to measurable product metrics such as:

- transaction completion rate
- abandonment rate
- task completion time
- login completion
- user confidence
- error rate

Do not claim that any metric has improved unless actual research or analytics data is provided.

---

## O — Output

Return the analysis using the following structure:

### 1. Executive Summary

Summarize the major UX opportunities.

### 2. User Persona

Include:

- name
- age
- occupation
- location
- goals
- behaviours
- frustrations
- needs
- motivation

Clearly distinguish assumptions from research evidence.

### 3. User Journey

Map:

Open App
→ Login
→ Home
→ Send Money
→ Recipient Verification
→ Transaction Review
→ Confirmation
→ Success

Identify possible friction at each stage.

### 4. Friction Audit

Use a table with:

| Stage | Friction | User Concern | UX Risk | Design Opportunity |

### 5. Trust Barriers

Identify potential trust barriers related to:

- security
- recipient verification
- fees
- transaction status
- privacy

### 6. UX Recommendations

For each recommendation provide:

Problem
→ User impact
→ Design response
→ Expected UX benefit

### 7. Screen Recommendations

Provide recommendations specifically for:

- Login
- Home
- Transaction Review

### 8. Accessibility

Identify accessibility improvements.

### 9. Privacy

Identify privacy-by-design considerations.

### 10. Success Metrics

Recommend measurable UX and business metrics.

### 11. Design Priorities

Prioritize recommendations according to:

- user impact
- transaction risk
- trust impact
- implementation complexity

Do not produce an overall winner or score.

---

## S — Style

Use:

- clear professional UX language
- concise explanations
- evidence-based reasoning
- problem → impact → solution structure
- fintech terminology where appropriate
- accessible language
- practical recommendations

Avoid:

- unsupported statistics
- fabricated user research
- fabricated interviews
- fabricated usability tests
- invented customer quotes
- claims of regulatory compliance
- exaggerated AI claims

When evidence is unavailable, explicitly label the statement as:

"Assumption"

"Hypothesis"

or

"Requires validation."

---

# Final Instruction

Treat AI as an assistant to the UX design process.

Do not replace human research with generated assumptions.

The purpose of the output is to help the designer identify questions, opportunities and hypotheses that can later be validated through real users, usability testing and product analytics.
